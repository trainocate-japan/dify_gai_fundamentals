# 役割
あなたは、ユーザーと対話しながら実務的なスライド図解を完成させる専門エージェントです。
独断で作成せず、必ずユーザーの意図を確認しながら段階的に進めてください。
ユーザーへの質問は、一度に一つ、短く簡潔に行ってください。

# 実行プロセス
1. 目的の確認: 最初に「何のための資料か」を短く聞いてください。
2. 内容の提案: 添付資料がある場合は、その内容のみを元にして3つの要点を提案してください。資料がない場合や、どうしても情報が不足している場合のみ、検索ツールを使用して補足してください。
3. ブラッシュアップ: ユーザーから要望があれば、資料の内容を優先して詳細情報を追加してください。
4. レイアウト選択: 内容が決まったら、最適なレイアウト（A, B, C, D）を提案してください。
5. SVG作成: すべての合意が取れたら、以下のルールに従ってSVGを作成してください。

# SVG作成ルール
1. 16:9のサイズ（viewBox="0 0 1600 900"）で作成すること。
2. フォントは「BIZ UDPGothic」または「BIZ UDPゴシック」を指定すること。
3. 背景、四角（rect）、文字（text）のタグのみを使用すること。
4. フォントサイズはタイトルが50px、本文は25px程度とすること。
5. 説明文が長い場合は、20文字程度で適宜改行（複数のtextタグ）を入れること。
6. 背景色は #F4F7F9、四角は #FFFFFF、枠線は #007BFF とすること。

# レイアウトの座標指定
レイアウトA（横に3つ並列）
- 四角1: x=100, y=300, 幅=400, 高さ=500
- 四角2: x=600, y=300, 幅=400, 高さ=500
- 四角3: x=1100, y=300, 幅=400, 高さ=500

レイアウトB（縦に3つリスト）
- 四角1: x=200, y=220, 幅=1200, 高さ=180
- 四角2: x=200, y=440, 幅=1200, 高さ=180
- 四角3: x=200, y=660, 幅=1200, 高さ=180

レイアウトC（左右に2つ比較）
- 四角1: x=150, y=250, 幅=600, 高さ=550
- 四角2: x=850, y=250, 幅=600, 高さ=550

レイアウトD（中央強調・上下テキスト）
- リード文（ボックスなし）: y=220 の位置に中央揃えで配置
- 中央四角: x=300, y=300, 幅=1000, 高さ=400
- フッター文（ボックスなし）: y=800 の位置に中央揃えで配置

# 出力形式
1. メッセージ: ユーザーへの質問や確認事項。
2. 作成の意図: 合意形成後の場合のみ記載。
3. SVGコード: 合意形成後の場合のみ、svgコードブロック（```svg ... ```）を出力。

SSHアクセス権がない状況でのトラブルシューティングは非常に歯がゆいものですが、ご推察の通り、**原因の9割以上は「Difyサーバーから外部インターネットへの通信（エグレス通信）が遮断されていること」**にあります。

エラー内容から推測される具体的な原因と、インフラ担当者に依頼すべき事項を整理しました。

---

## 1. エラーの原因分析

### ① webscraperの `npm install` エラー

DifyのWebScraperツールは内部でスクレイピングライブラリ（Playwrightなど）を使用しており、実行時に必要な依存パッケージを **npmレジストリ (`registry.npmjs.org`)** から取得しようとします。

* **原因:** サーバーが外部のnpmサーバーに接続できず、パッケージのダウンロードに失敗しています。

### ② プラグインがインストールできない

Difyのプラグインマーケットプレイスは、外部のレジストリや **GitHub** 上のリポジトリからデータを取得します。

* **原因:** プラグインのメタデータや本体ファイルを取得するための通信（HTTPS）がファイアウォールでブロックされています。

### ③ デフォルトモデルの設定が保存されない

一見ネットワークに関係なさそうですが、Difyはモデルの設定を保存する際、そのモデル（OpenAIやAnthropicなど）の **APIエンドポイントに対して疎通確認（バリデーション）** を行うことがあります。

* **原因:** モデルプロバイダーのAPIサーバーへの通信ができないため、バックエンド側で「無効な設定」と判断され、保存処理がロールバックまたは無視されている可能性があります。

---

## 2. ネットワーク構成の確認ポイント

SSH権限がない場合、ネットワーク管理者やクラウド管理者に以下の**「許可リスト（ホワイトリスト）」**への追加を依頼してください。

### 許可すべきドメイン/通信

| カテゴリ | 接続先ドメインの例 | 用途 |
| --- | --- | --- |
| **ツール依存** | `registry.npmjs.org` | WebScraperなどのライブラリ取得 |
| **プラグイン** | `github.com`, `objects.githubusercontent.com` | プラグイン本体のダウンロード |
| **モデルAPI** | `api.openai.com`, `api.anthropic.com` など | LLMとの通信・設定保存時の検証 |
| **Dify公式** | `marketplace.dify.ai` (将来的な拡張含む) | プラグイン一覧の取得 |

### 遮断のパターン

* **プロキシサーバーの未設定:** 組織内ネットワークで外部接続にプロキシが必要な場合、Dify（Dockerコンテナ内部）にプロキシ設定が渡っていない可能性があります。
* **セキュリティグループ/FW:** VM自体の外部送信（Egress）がHTTP/HTTPS（80/443ポート）を含め制限されている。

---

## 3. 対処法（管理者への依頼事項）

自分で操作ができないため、以下の内容をインフラ担当者に伝えて調査を依頼してください。

1. **コンテナ内からの疎通確認:**
「Difyの `api` コンテナおよび `worker` コンテナ内から `curl -I https://www.google.com` や `curl -I https://registry.npmjs.org` が成功するか確認してほしい」と伝えてください。
2. **環境変数の設定（プロキシがある場合）:**
プロキシ環境下であれば、`docker-compose.yaml` の `api` および `worker` サービスに以下の環境変数を追加し、再起動してもらう必要があります。
```yaml
HTTP_PROXY: http://your-proxy-server:port
HTTPS_PROXY: http://your-proxy-server:port
NO_PROXY: localhost,127.0.0.1,docker-endpoint

```


3. **DNS設定の確認:**
VMのDNS解決が正常か確認してもらってください。

## 4. SSHなしでできる唯一の確認

Difyの画面上で、**「モデルプロバイダー」の設定画面**を開き、現在利用しているAPIキーの横に「有効（動作中）」といった緑色のチェックマークが出ているか確認してください。ここがエラーになっている場合は、100%ネットワークの遮断です。

また、もし可能であれば、管理者の方に「Difyのログ（特に `api` コンテナと `worker` コンテナのログ）」を提供してもらうと、より詳細なタイムアウトエラーを確認できます。

**次に私がお手伝いできることはありますか？**
（例：管理者へ送るための詳細な調査依頼メールの文面を作成する、プロキシ設定が必要な場合の具体的な `docker-compose.yaml` の書き方を提示するなど）

研修の演習内容、素晴らしい仕上がりですね！
「自分で考え、調べ、対話し、形にする」というエージェントの醍醐味が凝縮されています。

エンジニアではない受講者の方が、迷わず5分〜10分程度でエージェントを立ち上げられるよう、**実際のDifyの操作画面をイメージした構築手順書**を作成しました。

## AIエージェント構築手順書：スライド図解秘書を作ろう

この手順では、Difyを使って「あなたの意図を汲み取り、プロ並みの図解を作成するAIエージェント」を構築します。

### 1. 新しいアプリを作成する

1. Difyのダッシュボードで「**アプリを作成**」ボタンをクリックします。
2. 「**最初から作成**」を選択します。
3. アプリの種類は「**チャットボット**」を選びます。
4. オーケストレーション（動作モード）で「**エージェント**」を選択してください。
* *注意：「ワークフロー」ではなく「エージェント」を選ぶのがポイントです。*


5. アプリに名前（例：スライド図解秘書）を付けて「作成」を押します。

### 研修で受講者に注目させるポイント

1. **AIの「意図」に気づく：**
「IT責任者向けか、一般社員向けか」というエージェントの逆質問が、**情報の取捨選択の基準**になっていることを解説してください。
2. **内容のブラッシュアップ：**
「2番を書き換えて」「手当のことも入れて」というユーザーのわがままに対し、エージェントが既存の情報をどう組み替えるかを見てもらいます。
3. **最後に完成したSVGを見る感動：**
複雑な長文が、対話を経てスッキリした3つのボックス（BIZ UDPゴシックの綺麗なフォント）に収まる瞬間が、ワークのクライマックスになります。

次は、もし受講者がSVGを作成した後に「やっぱり色を変えたい」「文字を大きくしたい」と言い出した時のための、**修正用クイック指示リスト**を作成しましょうか？

レイアウトC（比較）とレイアウトD（中央強調）が、エージェントによって必然的に選ばれるような「問いかけ方」と「やり取り」の案を作成しました。

受講者には、単に「まとめて」と言うのではなく、**「AとBを比べて」**や**「結論を一つだけ目立たせて」**といった、目的を明確にした指示を出してもらうのがポイントです。

### 研修で解説するためのポイント

* **レイアウトCの強み：**
